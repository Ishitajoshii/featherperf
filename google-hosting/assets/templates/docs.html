Install

Add the Vite plugin, then register it in your app config. Start narrow and conservative.

npm install @featherperf/vite-plugin
import { featherperf } from '@featherperf/vite-plugin';

export default {
  plugins: [
    featherperf({
      include: ['src/pages/'],
      exclude: [/hero/i],
      criticalSelectors: ['body', 'main', '.hero']
    })
  ]
};

Supported patterns

  • Best fit: below-the-fold motion modules triggered from page or script entrypoints.
  • Works well with GSAP and lottie-web when the importer shape is predictable.
  • Avoid marking hero or app-shell motion as deferrable until you have hard proof it is non-critical.

Configuration guidance

FeatherPerf is intentionally conservative. Protect useful content first, then expand coverage only after verifying the impact.

Recommended starting point
  • Keep include scoped to page and script entry layers.
  • Use exclude to keep hero-like selectors on the critical path.
  • Define explicit criticalSelectors for the app shell and top-of-page content.

What the plugin is trying to do

It does not try to rewrite arbitrary app behavior. It looks for safe motion-heavy imports and delays them until the associated section is near view or the page is otherwise quiet.

Good candidate

A decorative animation grid far below the fold.

Bad candidate

A hero animation that carries meaning for the first screen.

Verification mindset

Judge the result on observed browser behavior, not just plugin activity. The real win is that useful content renders earlier while non-critical motion wakes later without breaking the experience.
