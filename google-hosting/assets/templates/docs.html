FeatherPerf moves non-critical motion off the critical path.

Use FeatherPerf when a page pays an early performance tax for below-the-fold animation. The plugin keeps useful content on the first-render path, then wakes decorative motion later when it is relevant.

Quick start

Install the plugin, register it in Vite or Astro, and begin with a narrow include set plus explicit critical selectors.

npm install @featherperf/vite-plugin
import { featherperf } from '@featherperf/vite-plugin';

export default {
  plugins: [
    featherperf({
      include: ['src/pages/', 'src/scripts/'],
      exclude: [/hero/i],
      criticalSelectors: ['body', 'main', '.hero']
    })
  ]
};

Current benchmark claim

  • Controlled navigation proof: FCP improves from 2.748 s to 0.801 s.
  • Controlled interaction proof: hero-click INP improves from 52 ms to 25 ms.
  • Current story: early browser budget goes to useful content first, decorative motion second.

What FeatherPerf is good at

The best candidate is a motion-heavy page where the expensive section is clearly below the fold and not needed for the first useful render.

Good fit
  • Marketing or editorial pages with decorative GSAP or lottie-web sections.
  • Astro or Vite sites with a known non-critical motion module.
  • Pages where the hero and app shell should render before animation setup runs.

What not to do

FeatherPerf is intentionally conservative. It is not trying to lazy-load all JavaScript or guess around risky first-paint behavior.

Avoid deferring
  • Hero animation that carries meaning for the first screen.
  • Dynamic selectors or tightly coupled orchestration logic.
  • Modules with top-level side effects or return-value-sensitive calls.

Supported importer shapes

Today the plugin targets a small set of predictable patterns because safe coverage matters more than broad speculative coverage.

import { runMotion } from './motion';
runMotion('#gallery');

import { runMotion as runShowcase } from './motion';
runShowcase('#gallery');

import * as showcaseMotion from './motion';
showcaseMotion.runMotion('#gallery');

Safety rules

  • Prefer static selector strings.
  • Protect body, main, hero, header, and app shell selectors.
  • Use include and exclude aggressively during early rollout.
  • If the case looks uncertain, the plugin should skip it rather than guess.
